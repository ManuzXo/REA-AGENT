Come Claude Code parla con Ghidra tramite il server MCP rea-ghidra

Ci sono tre processi e due protocolli. Claude Code avvia node.exe rea.mjs mcp come processo figlio e gli parla in JSON-RPC 2.0 su stdin e stdout. Quando apri un binario, il server REA avvia a sua volta Ghidra headless con uno script Java che fa da ponte. Il server e il ponte si parlano con righe JSON su una porta TCP locale, autenticate da un token casuale.

Nessuno dei due protocolli passa dalla rete. Il client non sa nulla di Ghidra. Vede solo 207 tool MCP con nome, descrizione e schema.

I due protocolli a confronto

Client ↔ server (MCP)Server ↔ Ghidra (bridge REA)
Trasportostdin/stdout del processo figlioTCP su 127.0.0.1, porta scelta dal bridge. Socket Unix fuori da Windows
FormatoJSON-RPC 2.0, un messaggio per rigaJSON per riga, chiavi esatte id, token, method, params
Risposta{jsonrpc, id, result | error}{id, ok: true, result} oppure {id, ok: false, error{code, message}}
AutenticazioneNessuna. Il canale è privato del processoToken di 32 byte generato a ogni avvio, ripetuto in ogni richiesta
ConcorrenzaPiù richieste in volo, legate dall'idCoda FIFO, un'operazione sul Program alla volta
Chi lo definisceStandard MCPREA, interno. Mai visto dal client

Dove sta nel repository

  • scripts/rea-profiles.ps1 registra il server. Register-ReaClaudeMcp chiama claude mcp add-json --scope local con type: stdio, il comando Node e le variabili del profilo.
  • scripts/rea-runtime.ps1 installa REA con npm ci in .tools/rea-runtime/6.5.0 e lo pubblica solo dopo che initialize, tools/list e binary_session passano.
  • scripts/test-mcp.mjs è un client MCP minimale. Fa esattamente la fase 1 della sequenza e poi chiama binary_session. È il modo più rapido per vedere il protocollo dal vivo.
  • .rea/profiles/ghidra.json contiene REA_ANALYSIS_PROVIDER=ghidra, GHIDRA_INSTALL_DIR e JAVA_HOME, che diventano l'ambiente del processo server.
  • Nel pacchetto REA. dist/ghidra/GhidraLauncher.js costruisce la riga di analyzeHeadless, GhidraSocketConnection.js e GhidraClientWire.js gestiscono il bridge, bridge/ghidra/ReaGhidraBridge.java è il lato Java.

Cose da sapere

  • Lo stdout del server deve contenere solo JSON. Qualsiasi testo stampato lì rompe il client. test-mcp.mjs fallisce apposta in quel caso. I log vanno su stderr.
  • Claude Code legge la registrazione all'avvio. Dopo un nuovo Register serve riavviare o riconnettere il server. Il rapporto ghidra-mcp-fix-verification.md documenta proprio una sessione rimasta col vecchio errore.
  • Il guasto storico era nel lancio via npx. Una cache npm con ws/wrapper.mjs vuoto faceva morire Node prima della risposta a initialize. Oggi la registrazione lancia Node direttamente sul runtime locale bloccato dal lockfile.
  • Ghidra lavora su una copia del binario, verificata con SHA-256. Il file originale non viene toccato e il campione non viene eseguito.
